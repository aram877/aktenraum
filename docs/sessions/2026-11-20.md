## Fixed: chunk-space reconcile raced the api at worker start

- **Symptom (during the deploy):** after a full rebuild every startup space lookup failed with `fetch failed` (`index_space_reconcile_failed` per document, 19:22:17.7 vs api listening at 19:22:18.1) and nothing retried. The worker only soft-depends on aktenraum-api (`service_started`), and the per-document `catch` made the whole reconcile count as a success. Harmless this time (no moves yet on the live stack).
- **Fix:** `reconcileChunkSpaces` (`services/auto-tagger/src/indexer.ts`) is its own startup step in `main.ts` under `retryUntilSuccess` (30 s × 10). It returns the failed doc ids; the step throws while any remain and the next attempt re-checks only those. `enqueueUnindexedDocuments` no longer does space work, so a retry never re-enqueues indexing jobs. One warning per attempt instead of one per document.
- **Tests:** worker 148 → 150 (old combined test replaced by three: stale/unassigned/failed mix, retry-only-failed, api-down-then-up through `retryUntilSuccess`).
- **Live check:** restarted api + worker together → `index_space_reconcile_failed attempt 1 "80 documents failed: fetch failed"`, then `index_space_reconcile_completed` 30 s later.
