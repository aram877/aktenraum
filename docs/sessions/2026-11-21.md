## What shipped (by feature)

### Sessions replace the JWT (api)

- New tables `sessions`, `auth_rate_limit_events`, `auth_audit` (`schema.sql`, `schema.ts`, pg-mem harness). Checked on a throwaway `postgres:15`: applies twice; unique `token_hash`, both CHECKs, the audit CHECK and the `member_id` FK reject bad rows.
- `auth/session.service.ts`: 32-byte base64url token, sha256 stored; `__Host-aktenraum_session` (Secure) with `COOKIE_SECURE=true`, else `aktenraum_session`; Max-Age = `SESSION_ABSOLUTE_DAYS`. 7 d idle / 30 d absolute (`SESSION_IDLE_DAYS`, `SESSION_ABSOLUTE_DAYS`); idle slide ≤ 1/min via `CASE` (pg-mem has no `least()`).
- `AuthGuard` resolves the session (one indexed query, 0.03 ms on Postgres) and sets `sessionId` + `authTime`. `auth/jwt.ts`, `pwf`, `jsonwebtoken`, `JWT_SECRET`, `JWT_EXPIRES_SECONDS`, `LoginThrottle` removed.
- Revocation: logout (server-side, unguarded), password change (all of the member's sessions), member removal lockout (`member_removed`, actor = admin).
- Device list routes: `GET /api/auth/sessions`, `DELETE /api/auth/sessions/:id` (own only, else 404), `POST /api/auth/sessions/revoke-others`.
- Live-counts stream re-checks `SessionService.state` each tick → `session_ended` `revoked` / `expired` (a removed member's session counts as revoked). Replaces the removal-only check.
- `app.set("trust proxy", 1)` in `main.ts` + harness.

### Login protection + audit (api)

- `AuthRateLimiter` (Postgres): `login:user:<name>` + `login:ip:<addr>` for login (either throttles; success resets only the username), `invite:ip:<addr>` for invites. Survives restarts.
- `AuthAuditService` → `auth_audit` (login succeeded/failed/throttled, logout, session_revoked per session, password_changed, invite_redeemed). `AuthSweepService` prunes hourly.
