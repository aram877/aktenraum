## Credentials & secrets

**First-run flow (Phase 0.1, ADR-002).** `task setup` (`scripts/first-run.sh`) is the whole install; tested end to end from an empty folder on 2026-10-01 under a separate compose project. All runtime secrets except `PAPERLESS_API_TOKEN` are auto-generated by `bash scripts/bootstrap-secrets.sh` — it copies `docker/.env.example` → `docker/.env` if absent, fills empty REQUIRED values with `openssl rand`, and prints the auto-generated admin/SPA passwords ONCE for the user to record. The script is idempotent: re-runs are safe no-ops once everything is populated, which is why the future desktop shell will call it on every launch as a safety net. `PAPERLESS_API_TOKEN` still has to be minted via the Paperless API after the paperless container starts (see `scripts/bootstrap-paperless.sh`).

| What                   | Where                                                                                                                                                                                                                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Paperless URL          | http://localhost:8000 (admin UI, only used for backend tasks)                                                                                                                                                                                                       |
| aktenraum URL          | http://localhost:8080 (SPA — primary user interface)                                                                                                                                                                                                                |
| Paperless admin        | `PAPERLESS_ADMIN_USER` / `PAPERLESS_ADMIN_PASSWORD` in `docker/.env`                                                                                                                                                                                                |
| aktenraum admin        | `BOOTSTRAP_USERNAME` in `docker/.env` (seeded on first start, ignored once a user exists). `BOOTSTRAP_PASSWORD` stays **empty** on new installs → passwordless admin, `first-run.sh` prints a setup link. Sign-in is by passkey (auth-passkeys); lost everything → `docs/runbooks/locked-out.md`. |
| Passkey addresses      | `WEBAUTHN_ORIGINS` (default `http://localhost:8080,http://localhost:4300`) / `WEBAUTHN_RP_IDS` (default `localhost`) in `docker/.env`, optional. A passkey works only on the host name it was created on; IP addresses are refused at startup. |
| aktenraum sessions     | Server-side, `sessions` table (no signing key). `SESSION_IDLE_DAYS` (7) / `SESSION_ABSOLUTE_DAYS` (30) in `docker/.env`, optional. `JWT_SECRET` / `JWT_EXPIRES_SECONDS` are retired (unused; existing `.env` files keep them for a code rollback). |
| Member token key       | `AKTENRAUM_SECRET_KEY` in `docker/.env` — required, 32 bytes base64, generated by `bootstrap-secrets.sh`. Encrypts each member's Paperless API token (`member_paperless_tokens`, AES-256-GCM). Changing it only forces a re-mint. |
| Paperless DB password  | `PAPERLESS_DBPASS` in `docker/.env`                                                                                                                                                                                                    |
| Paperless API token    | `PAPERLESS_API_TOKEN` in `docker/.env` (mint via `POST /api/token/` after first paperless boot — example below)                                                                                                                                          |
| Restic passphrase      | `RESTIC_PASSWORD` in `docker/.env`                                                                                                                                                                                                                            |
| Qdrant API key         | `QDRANT_API_KEY` in `docker/.env` — required (compose refuses to start without it); Qdrant answers 401 to anything without the `api-key` header. Generated by `bootstrap-secrets.sh`. |
| Service credentials    | `SVC_TOKEN_PAPERLESS_HOOK` / `SVC_TOKEN_WORKER` / `SVC_TOKEN_API` in `docker/.env` (ADR-010 step 5, `service-credentials`) — one per internal caller, sent as `Authorization: Bearer`, generated by `bootstrap-secrets.sh` as `akt_svc_` + 43 base64url chars. Allowance: hook → worker `/trigger/extract` only; api → worker `/trigger/*` + `/processing`; worker → api only its scoped routes (`/api/settings/active-*`, type-fields PATCH, `/api/tenancy/*`). Known caller outside its allowance → 403 at the worker; non-worker credential at the api → 401. **Fail-closed**: empty → calls needing it are rejected, `service_token_unset` at startup; equal values → both unset, `service_token_duplicate`. One check: `serviceCaller` in `@aktenraum/core` (`secrets.ts`, over `secretMatches`), used by the worker's webhook (`ALLOWED` table) and the api's `InternalGuard` / `UserOrInternalGuard`. Compose blanks what a container doesn't use: Paperless sees only the hook token (as `AKTENRAUM_HOOK_TOKEN`), the api never the hook token, backup none. `WEBHOOK_SECRET` / `X-Aktenraum-Secret` are retired (the value stays in existing `.env` files for a code rollback). |
| Personal access tokens | No env var (ADR-010 step 6, `personal-access-tokens`). A member creates `akt_pat_…` tokens (43 base64url chars after the prefix, shown once, sha256 stored) in `/settings → Konto → Zugriffstokens` — step-up, name, scopes from `documents:read|write|delete`, `upload`, `ai:ask`, `settings:read`, `shares:manage`, `spaces:manage` (never `household:admin` / `settings:write`), 1–365 days, ≤ 25 active. Scripts send `Authorization: Bearer akt_pat_…`; effective scopes = token ∩ role. A leaked token: revoke it in the list (`docs/runbooks/rotate-api-keys.md`). |
| auto-tagger → api      | `AKTENRAUM_API_URL` in `docker/.env` (default `http://aktenraum-api:8002`). Used for type-specific extraction PATCH + the per-DocumentType auto-approve rule fetch.                                                                                       |
| LLM backend            | `LLM_BACKEND=ollama` or `anthropic` in `docker/.env` (shared by both auto-tagger and aktenraum-api)                                                                                                                                         |
| Ollama model           | **NOTE: `OLLAMA_MODEL` is only a fallback.** The live extraction/answer model is the literal model tag stored in `app_settings.llm_model` / `answer_llm_model` (picked in `/settings`), not this env var (see the Known-gotcha row). `OLLAMA_MODEL=qwen2.5:14b-instruct-q8_0` (~16 GB) is used only when the api is unreachable. Smaller models (≤8B) reliably drop schema fields — the synthesizer fallbacks catch them but the output is less specific. Both `OLLAMA_MODEL` and `OLLAMA_ANSWER_MODEL` are in `docker/.env`. |
| Embedding model        | `EMBEDDING_MODEL=qwen3-embedding:4b` (2560-dim) in `docker/.env` — single entry, shared by both auto-tagger (indexing) and aktenraum-api (query). Pull with `ollama pull qwen3-embedding:4b`. Dimension is pinned in `@aktenraum/core rag.DENSE_DIM`; changing the model to a different dim requires `task rag:reembed`. (Migrated off bge-m3/1024 on 2026-06-22.) |
| AI search → Paperless  | `PAPERLESS_API_TOKEN` in `docker/.env` — shared token used by both auto-tagger and aktenraum-api; required for `/api/ai/*`                                                                                                                                                     |
| AI search → LLM        | `ANTHROPIC_API_KEY` (when `LLM_BACKEND=anthropic`) or `OLLAMA_BASE_URL` + `OLLAMA_MODEL` (when `LLM_BACKEND=ollama`), all in `docker/.env`                                                                                                             |
| AI answer → bigger LLM | Optional `OLLAMA_ANSWER_MODEL` / `ANTHROPIC_ANSWER_MODEL` in `docker/.env` — overrides the model used by `/api/ai/answer/stream` only; pair a fast small model for filter extraction with a smarter big one for prose answers (8B is too small to read citations reliably; 14B+ recommended) |

Env files are gitignored. Example: `docker/.env.example` (single unified file — all services load from `docker/.env`). The API token is **per-database** — a fresh `pgdata/` means re-minting.
