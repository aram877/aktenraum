## Follow-up: the nightly backup never ran (catch-up scheduling + SPA warning)

### Diagnosis

- None of the 20 restic snapshots was taken by cron. All came from setup or manual runs; the newest was 2026-10-16 (34 days old).
- The cron job was `0 2 * * *` UTC (03:00 local). The Windows event log shows the PC asleep from about midnight to 10:00. BusyBox crond doesn't catch up missed jobs, so on this host the job could never fire.

### What shipped

- **Catch-up scheduling** (`docker/backup/`):
  - `backup-if-due.sh`, hourly at :07: backs up when the newest complete backup (the oldest of the three per-tag latest snapshots) is older than `BACKUP_INTERVAL_HOURS` (20), otherwise exits silently.
  - `start.sh` (new CMD): writes the status file, runs the catch-up check after `BACKUP_START_DELAY_SECONDS` (60), then `exec crond`.
  - `entrypoint.sh`:
    - an flock, so manual and scheduled runs can't overlap
    - an EXIT trap that writes `last-run` (time + exit code) and refreshes the status, also on `set -e` aborts
    - `restic check` keyed on "≥ 7 days since `last-check`" instead of Sundays
- **Backup health in the SPA**:
  - `healthcheck.sh` writes `backup-status.json` into the new `backup-status` volume (rw for backup, ro for the api).
  - `GET /api/health/backup` (session-guarded, `health/backup-status.ts`) returns `ok`/`stale`/`failing`/`unknown`. `failing` also covers a failed last run, an unreadable repository, and a status file older than 3 h.
  - The nav shows an amber "Backup veraltet" or red "Backup-Fehler" pill linking to the new **Settings → Backup** section (`components/settings/Backup.vue`).
- **Docs**: CLAUDE.md (known-gotcha row, backup section, test counts), configuration, api-reference, operations, first-time setup, architecture overview + diagram.

### Found, not fixed (pre-existing, Windows / Git Bash) — needs the maintainer's OK as a bug fix

`scripts/e2e-worker.sh` cannot run as-is on this Windows host; the rehearsal used a scratchpad shim instead of changing the repo:
1. `PY="$(command -v python3 || command -v python)"` picks the Microsoft Store `python3` stub ("Python was not found", exit 49). Same detection in `bootstrap-paperless.sh`.
2. Windows Python decodes piped stdin as cp1252, so `Behördenbrief` / `Bußgeldbescheid` / `Kündigung` arrive mangled in the auto-approve PUT → 422 (curl exit 22). `PYTHONUTF8=1` fixes it.
3. `mktemp` returns an MSYS `/tmp/...` path that native curl can't read for `-F document=@…` (curl exit 26).
Fix sketch: probe `"$cand" -c ''` before accepting an interpreter, export `PYTHONUTF8=1`, and create the upload file under a `cygpath -m`-converted temp dir.
