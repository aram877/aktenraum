# Follow-up — `e2e-api-qdrant` (proposed + implemented)

## Focus / scope
Take the one backlog item: the throwaway e2e api ran with `QDRANT_URL=""` (to dodge the reranker OOM), so no rehearsal could check the Qdrant payloads the **api** writes (shares, moves, removals, trash flags).

## What shipped
- api: `RERANKER_ENABLED` (bool, default `true`, `config/settings.ts`). `false` → `RetrievalModule` builds no `LocalReranker` (no download / prewarm / lazy load), logs `reranker_disabled`; `RetrievalDeps.reranker` is nullable; `retrieval.ts` shares one `denseOrder` helper between the no-reranker branch and the rerank-failure fallback; `rag_retrieve_complete` gains `reranker_used`. The eval runner honours the switch. New `ai/retrieval.test.ts` (5 tests).
- e2e: `docker-compose.e2e.yml` api gets `QDRANT_URL`, `QDRANT_API_KEY`, `RERANKER_ENABLED=false`. `e2e-worker.sh` trashes + restores the indexed document through the api and asserts `trashed` true/false on every chunk.
- Rehearsals: `share-rehearsal.mjs` and `removal-rehearsal.mjs` had been broken since `auth-passkeys` (2026-11-21) — they still used password login + `/invites/:token/redeem`. New `scripts/spikes/rehearsal-auth.mjs` (`adminMember` via host-CLI setup link, `joinWithPasskey`, step-up-aware `call` that retries once after a soft-authenticator step-up, `upload`, `anonymous`); both scripts ported. Removal rehearsal asserts the api's own chunk-space rewrite before the worker-reconcile check.
- Docs: `configuration.md` (variable, "leave unset in production"), CLAUDE.md, backlog emptied (also dropped the superseded live-counts entry).
