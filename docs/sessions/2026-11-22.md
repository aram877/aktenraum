# Follow-up — live-counts reconnect storm (bug fix, awaiting the maintainer's confirmation)

## Report
Maintainer: `/api/auth/me` and `/api/events/counts` called non-stop. nginx: 8,478 / 8,477 requests in one minute (~140/s each); every stream answered 200 with 47 bytes = `event: session_ended / data: revoked`.

## Root cause
`SessionService.state()` (per-tick check of the live-counts stream, since `auth-server-sessions` 2026-11-21) built `EXISTS (SELECT 1 FROM member_removals WHERE member_removals.member_id = ${sessions.memberId})`; in a single-table select drizzle renders the outer column unqualified, so the subquery compared `member_removals.member_id` with itself. The live DB has one removal (suzanna, member 2, 2026-11-20) → every session "revoked". Confirmed in psql on session 6: unqualified form `true`, qualified form `false`. `/auth/me` uses another query, said OK, the SPA restarted the stream immediately → loop. Probably running whenever a tab was open since 2026-11-21.

## Fix (uncommitted — bug-fix rule)
- api: uncorrelated `IN (SELECT "member_id" FROM "member_removals")`; unused import dropped. Regression test in `household/member-removal.routes.test.ts` (failed before the fix with exactly `session_ended / revoked`, passes after; the removed member's own stream still ends).
- web: `createLiveCountsStream` backs off after `session_ended` (5 s doubling to 60 s, reset by a counts frame); test in `tests/nuxt/live-counts.spec.ts`.
- No other correlated `EXISTS` in api `src`.
- Tests 1279 → 1281 (api 577, web 311); lint + both typechecks green.
- Live: api + nginx rebuilt; library open 16 s in Chrome → 1 `/auth/me`, 1 stream held open until the tab closed (60 bytes, one counts frame).
