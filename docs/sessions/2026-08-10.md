## Findings worth carrying forward

Four things this session surfaced that are not obvious from the code:

1. **NestJS response-shape defaults silently break the SPA contract.** Nest emits `{statusCode, message, error}` where FastAPI emits `{detail}`, and `apps/web/src/lib/ai.ts` parses `{detail}` explicitly. Nest also returns **201** from any `@Post()` where FastAPI returns 200. Both are now handled globally (`FastApiErrorShapeFilter`, explicit `@HttpCode`), but every future route needs the status checked against its Python counterpart rather than assumed.
2. **Drizzle returns different wire formats than Pydantic did.** Timestamps come back as Postgres's `2026-08-10 08:46:08.5+00`, which `new Date()` parses in V8 but **not in Safari** — it would have silently blanked the "last changed" column on iOS while looking fine in Chrome dev. `numeric` columns come back as strings. Hit twice already; assume a third case exists.
3. **JavaScript's `\b` is ASCII-only.** A naive port of the German intent classifier's `\blohn\b` matches "Lohnübersicht" where Python's Unicode-aware `\w` does not. Now uses explicit `\p{L}`-based lookarounds.
4. **vitest's esbuild transform drops `emitDecoratorMetadata`**, so Nest's type-based DI resolves every service to `undefined` and every route 500s — while the app itself works fine under `tsc`. Fixed with `unplugin-swc`. The failure presents as an application DI bug, not a build-config problem.
