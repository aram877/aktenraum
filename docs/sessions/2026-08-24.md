### 6.7 — worker test suite complete (64 → 105 tests)

Closed the remaining gaps: prompt assembly, the correspondent-history hint,
few-shot exemplar rendering, and the two tag-inspection helpers in
`extract.ts` including the `isUntrustedSource` prompt-injection guard.

Two of these tests encode rules that are easy to break by accident.
`formatHistoryHint` must **not** claim a dominant type from a single sample
even though one document is trivially 100% of the history — the Python
requires ≥2 samples, and a port that dropped that check would confidently
mis-hint every first document from a new sender. `buildHistoryHint` matches
the longest known correspondent name first, so "AOK NordWest" cannot lose to
"AOK". `SYSTEM_PROMPT` is pinned by exact length and by its six
disambiguation markers, so a careless edit to the German prompt fails the
suite rather than silently changing extraction behaviour.

`loops.ts` / `main.ts` / `config.ts` stay untested by design — pure wiring,
mirroring Python's untested `main.py`.

### 6.8 — isolated snapshot stack

`docker/docker-compose.e2e.yml` (project `aktenraum-e2e`) with its own named
volumes, network and ports, driven by `task e2e:worker` / `task e2e:down`.
The driver script hard-refuses to start if any configured port belongs to the
live stack, because the failure mode being designed against is a Node worker
and a Python worker racing on the same lifecycle tags.

Three things had to change to get it up. `post_consume.sh` hardcoded
`http://auto-tagger:8001`, so it now honours `AKTENRAUM_AUTO_TAGGER_URL` with
that URL as the default (live behaviour is unchanged). `worker-node` had no
Dockerfile. And the e2e API runs with `QDRANT_URL=""`, which short-circuits
`RetrievalModule` and skips the ~571 MB reranker prewarm — with the live stack
also running, the 7.7 GB Docker VM OOM-killed it (exit 137). The worker keeps
`QDRANT_URL` set, so indexing still runs and is asserted directly against
Qdrant.

### 6.9 — end-to-end run: 20 assertions, all passing

`scripts/e2e-worker.sh` mints a token on the throwaway database, bootstraps

## Bug found: the Node stack could not create its own database schema

The e2e run found this, not the task list, and it would have broken every new
install the moment 4.15 deleted the Python API.

Alembic ran from the **Python** API's container entrypoint. The Node API has
`src/db/0000_certain_guardian.sql`, but that is drizzle-kit *introspection*
output: the whole body is inside a `/* ... */` block, deliberately kept
byte-identical to the generator so it can serve as a drift oracle. Nothing
applied it. Against the fresh e2e database the Node API logged
`api_start_failed … Failed query: select "id" from "users"` and exited.

Fixed with `src/db/schema.sql` — the same DDL, uncommented, every statement
`CREATE TABLE IF NOT EXISTS` — applied in one transaction by `applySchema()`
before `NestFactory.create`. It seeds `alembic_version` with `0006` only when
the table is empty, so a Python API redeployed during the 6.11 rollback window
sees an up-to-date database rather than replaying migrations onto tables that
already exist. Auto-approve rows are not seeded here; the ported
`reconcileMissingRules()` already inserts all 27 on startup (confirmed live:
`auto_approve_rules_reconciled inserted=27`).

`tsc` emits only JS, so the Dockerfile copies the SQL into `dist/db/`. Five
tests in `apply-schema.test.ts` guard it: every Drizzle table has matching
DDL, every `CREATE TABLE` is guarded, the file contains no `DROP`/`TRUNCATE`/
`DELETE`, the `alembic_version` seed is conditional, and the column lists
still match the introspection it was derived from.

## Decisions and divergences recorded

- **`asyncio.shield()` has no Node equivalent, and needs none.** The Python
  shields the lifecycle-flipping PATCH against cancellation on SIGTERM. In
  Node an in-flight `await` is not cancelled by a signal — shutdown sets an
  abort flag and closes queues, and anything already in flight completes. The
  guarantee comes for free; do not add cancellation support later without
  restoring an equivalent guard.
- **`PaperlessClient.getTagId` is now public** in `core-ts`. The Python reaches
  into `_get_tag_id` with a `noqa` for exactly this read-only lookup.
- **One accepted cosmetic divergence** in the few-shot block: Python's
  `json.dumps` renders the float default `1.0`, `JSON.stringify` renders `1`.
  Only reachable when an exemplar has no `ai_confidence` field at all. Forcing
  it would need a sentinel-token string replace that risks emitting malformed
  JSON into the prompt.

## Things that needed real work, not just renaming

- **The Angular build output path.** Angular emitted to `dist/web-angular/browser`;
  the nginx Dockerfile copies `apps/web/dist`. Set
  `outputPath: {base: "dist", browser: ""}` so the existing COPY works and the
  Dockerfile did not have to learn Angular's layout.
- **`git mv` into a directory that still existed on disk.** `git rm -r` clears
  the index but leaves untracked leftovers, so
  `git mv services/api-node services/aktenraum-api` nested the source *inside*
  the old Python directory instead of replacing it. Had to flatten by hand.
- **A Node RAG backfill did not exist.** `scripts/backfill-rag-index.sh` shelled
  into the Python worker. Wrote `auto-tagger/src/backfill.ts` (same JSON-line
  event protocol, same skip-if-already-indexed semantics) plus
  `drop-collection.ts` for `task rag:reembed`, which needed a new
  `QdrantVectorStore.dropCollection()` — `ensureCollection()` only ever
  CREATEs, so there was no way to recover from a dimension change.
- **`task paperless:bootstrap`** ran a Python module inside the container. It
  now calls `scripts/bootstrap-paperless.sh`, which is pure bash + curl and is
  already what the e2e harness uses.
- **The dev overlay** was uvicorn `--reload` + watchfiles. Rewritten to
  bind-mount `src/` and run `tsx watch` in both services.
